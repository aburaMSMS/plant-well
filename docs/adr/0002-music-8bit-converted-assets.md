# BGM 用 8-bit 化的真实曲目，程序合成音序器降级为兜底

M6 时没有任何音乐素材，我们写了纯程序合成的方波音序器当 BGM（零素材、零依赖）。现在用户提供了两首真实曲目（`src/assets/title.mp3` / `游戏中.mp3`），决定：**真实曲目经离线转码成 8-bit 风格 WAV 后作为主 BGM**（标题一首、井内一首），原来的音序器只在素材加载失败（如 file:// 直开页面）时兜底。转码而非运行时合成，是因为"8-bit 化"要的是可复现的一次性产物：两遍式响度归一（-16 LUFS，切歌不惊跳）→ 双低通限带宽 → 16kHz 重采样 → 8-bit 量化（`scripts/convert-music.mjs`，换曲子重跑 `npm run convert:music` 即可）；运行时只做 fetch + decodeAudioData + BufferSource 循环，依然零运行时依赖。没有选"扒谱重合成芯片音"（听感最正宗但要人工扒旋律，成本不成比例），也没有选在浏览器里实时 bit-crush MP3（每次加载都白算一遍，产物还不可审查）。

## Consequences

- dist 增加 ~5.5MB（mono/16kHz/8bit WAV 约 16KB/s）；若将来嫌大可降采样率或换有损容器
- 音色是"lo-fi 采样"而非正宗芯片重合成；要更进一步需人工扒谱进音序器
- 曲目经 musicGain（0.5）单独走线再进 master，音量/静音沿用主增益；两首已归一到同响度，切换不炸耳
