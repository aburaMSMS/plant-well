# M6 讲解：存档、标题、改键与无文字的结局

## flags 是唯一事实源

所有谜题状态（门、藤、花苞、机关、源种、道具）都活在 `world.flags` / `world.seeds` / `world.items` 三个集合里。存档因此只是把三个集合加一个位置序列化成 JSON 进 localStorage：

```json
{ "room": [1,0], "x": 315, "y": 94, "items": [], "active": null, "seeds": [], "flags": [] }
```

存档时机：房间转换、任何拾取、任何 flag 变化、暂停。读档 = 按存档重放集合 + 装载房间。**不存在"实体自己的状态"这回事**，所以永远不会有"门开了但存档里没记"的漂移。结局时清除存档——井恢复原样，像什么都没发生过。

## 无文字的信息设计

游戏进行中没有一个汉字或单词，但玩家需要的四种信息都有图形答案：

- **进度**（差多少）→ HUD 右下 10 个源种槽；走近巨花时它身上的 10 个凹槽亮起同样多的数目
- **持有与手持**（有什么、拿着什么）→ HUD 左下三格道具图标，手持的那格带框
- **刚学到什么**（这个键干嘛的）→ 拾取道具时短暂弹出道具图标 + 使用键的键帽图形
- **该做什么**（结局条件）→ 凹槽随收集数变亮本身就是进度条，集满时巨花变暖色开始呼吸——状态即提示

文字只出现在标题画面（操作说明、改键菜单），这是访谈时定下的边界。

## 改键：捕获模式的输入

改键 UI 的核心是"捕获下一个物理键"：`Input.captureNext(cb)` 让下一个 keydown 不进动作系统、直接回调（Esc 取消）。绑定数据用 `event.code`（物理键位），换布局不改键位；保存进 localStorage，加载时与默认表合并（新动作自动补默认键）。

一键不绑两用：`rebind` 先从所有动作上摘掉这个键再绑上，避免歧义。

## 结局：两段式状态机

- **绽放**（`ending`，4 秒）：巨花变暖色、花瓣张开（对玩家仍不可见细节也没关系——光圈半径每秒膨胀 220px + 金色粒子 + 上行和弦），2.2s 起白色渐隐
- **尾声**（`epilogue`）：黑屏，一粒种子落下、静止、抽芽、双叶展开，标题浮现。4.5s 后任意确认键回标题

两段都是 `endingT` / `epilogueT` 计时器驱动的纯函数，输入被锁，不与任何游戏系统耦合——结局是"演出"，不该因为玩家按了方向键而出戏。

## 标题菜单的导航即测试

标题菜单直接复用动作系统（up/down/confirm 导航），这意味着改键自动对菜单生效。CONTINUE 项只在存档存在时出现；NEW GAME 永远可点（覆盖式开新档前先 `startNew()` 清空全部集合）。

## 自己动手

1. 给存档加"游戏时长"，在标题 CONTINUE 项下用小点点显示（每 10 分钟一个点）。
2. 死亡时的受击方向影响粒子喷射方向——`onHazardStart` 现在还不知道方向，把它传进去。
3. 结尾的种子落点改成"随收集源种数偏移"——给完美主义者一个重新开始的理由。
