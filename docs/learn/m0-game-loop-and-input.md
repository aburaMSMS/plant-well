# M0 讲解：游戏循环与输入系统

脚手架看上去"什么都没做"，但它决定了之后每个里程碑写起来顺不顺。这份文档讲三个文件里的关键设计，读完应该能回答：为什么逻辑要锁 60Hz？为什么按键事件不能直接用？为什么游戏逻辑不该问"J 键"？

## 1. 游戏循环（`src/engine/loop.ts`）

### 为什么不直接"每帧动一下"

新手写法是 `requestAnimationFrame` 里直接 `x += 2`。问题是 rAF 的频率等于显示器刷新率：144Hz 屏幕上游戏快 2.4 倍，掉帧时游戏变慢。**时间成了隐含变量**，而它必须显式。

两种正确解法：

1. **可变时间步**：每帧用真实帧长 `dt` 积分（`x += speed * dt`）。简单，但物理行为随帧率轻微漂移——同样的跳跃轨迹，60fps 和 144fps 落点不同。
2. **固定时间步**（我们选的）：逻辑永远按 1/60 秒一步演进，渲染随便多快。游戏模拟变成**确定性**的：同样的输入序列永远得到同样的结果。这是平台跳跃手感和之后所有调试的基础。

### 累加器模式

真实时间是不均匀 chunks 到达的（这帧 16.6ms，下帧 9ms）。循环把真实时间攒进 `accumulated`，攒够一个 `STEP` 就演进一步，可能一帧演 0 步（高刷屏）也可能演 3 步（掉帧）。

```ts
accumulated += Math.min((now - last) / 1000, MAX_FRAME_TIME);
while (accumulated >= STEP) { scene.update(); accumulated -= STEP; }
```

`MAX_FRAME_TIME = 0.25` 是**螺旋防护**：切后台半小时回来，如果老老实实累积 1800 秒，循环要跑 108000 步才能追上，期间画面完全冻结——表现就是"切回来卡死几秒甚至永久"。封顶后最多丢掉 0.25 秒，代价可忽略。

### 渲染没有插值（刻意的）

严格做法是渲染时在"上一步和这一步状态之间插值"，消除 60Hz 逻辑 + 144Hz 渲染的轻微卡顿。我们刻意没做：像素游戏位移小、插值会让像素半像素抖动，破坏像素感。等 M1 有了真实移动再回头感受这个问题。

## 2. 输入系统（`src/engine/input.ts`）

### 动作映射（action mapping）

游戏逻辑只问 `input.pressed("jump")`，永远不问 `e.code === "KeyJ"`。这不是洁癖：

- 改键 = 改一张映射表，游戏逻辑零改动
- 将来加手柄 = 往映射表里多加一种设备
- 动作名就是设计词汇（jump/use/confirm），读代码的人不需要知道"J 是跳"

### 为什么用 `event.code` 不用 `event.key`

`key` 是**产生的字符**：法语 AZERTY 键盘上物理 W 位置的键产生 `z`。`code` 是**物理键位**，WASD 在任何布局上都在左手原位。对动作游戏这是正确选择。

### 事件与逻辑步的时差（最容易错的地方）

按键事件异步到达，可能落在两次逻辑步之间，一帧甚至可能演多个逻辑步。直接在事件回调里改游戏状态 = 状态变化发生在"步与步之间"的无人区，破坏确定性。

我们的做法：事件回调只把事件**排队**（`queue`），每个逻辑步开头由 `update()` 统一结算——世界只在步的边界变化。

`justPressed` 的语义是"**本步**刚刚按下"：

- `update()` 开头先清空上一步的 justPressed，所以一次按键只在一个逻辑步里可见——跳跃不会因为掉帧卡了 3 步而触发 3 次
- 按*住*状态（`held`）跨步保留，直到收到 keyup
- `e.repeat` 的 keydown 事件直接丢弃：OS 自动重复不该伪造"新按下"

### 鬼按键

游戏失焦时 OS 不再给这个窗口送 keyup。按住 D 切去回微信，切回来角色会永远向右走。解法：监听 `blur`，直接清空全部按住状态。所有本地输入游戏都需要这个补丁，没有例外。

### 改键

`rebind(action, code)` 做三件事：从其他动作上摘掉这个键（一键不绑两用，避免歧义）、绑上、存 localStorage。改键 UI 在 M6 的标题画面做，但**数据结构和持久化现在就位**——好的顺序是先定数据，后补界面。

## 3. 显示（`src/engine/display.ts`）

内部分辨率 320×180（16:9，Animal Well 量级的粗像素），放大只取**整数倍**。非整数缩放会让每个游戏像素占 2.37 个屏幕像素，某些像素行比邻居宽/亮，像素画会闪烁。宁可四周留黑边，不用非整数。

`imageSmoothingEnabled = false` 关掉 canvas 的双线性插值，配合 CSS `image-rendering: pixelated`，放大后边缘是硬的。

## 自己动手（建议按顺序）

1. **疾跑**：按住 `jump` 时移动速度 ×1.6。需要 `held` 和 `pressed` 的区别想清楚。（提示：`input.held("jump")`）
2. **新动作**：加一个 `map` 动作绑在 `KeyL` 上，按下时在主角位置画一个小三角。（走一遍 Action 类型 → 默认绑定 → 使用的完整链路）
3. **感受确定性**：把 `STEP` 改成 `1/20`，观察移动变成"跳格"。再把 demo 里的 `SPEED / 60` 改成 `SPEED * STEP`，确认改回 `1/60` 后一切照旧——这就是为什么位移应该用 `STEP` 而不是魔法数字 60。
4. **螺旋实验**：把 `MAX_FRAME_TIME` 删掉，切到别的标签页 30 秒再切回来，感受螺旋卡死。（改完记得改回来）
