# M7 · 互动植被与泡泡顶替 —— 装饰怎么长出"规则"

> 本篇对应第五轮用户反馈迭代：草丛/藤蔓丛（路过摇摆）、护罩蹭藤蔓破裂、一井一泡。
> 核心话题只有一个：**一个东西属于"装饰"还是"玩法"，不取决于它长得像什么，取决于改它要不要走关卡数据。**

## 1. 同样是植物，为什么藤蔓是实体、草丛是装饰？

井里现在有三种植物，分属三个层次：

| | 草丛/灌木（decor.ts） | 藤蔓丛（HangingVine） | 藤蔓墙（VineBud） |
|---|---|---|---|
| 有判定区吗 | 没有 | 有（护罩会破） | 有（还是实心） |
| 放在哪 | 生成器按地表自动撒 | 关卡数据手放 | 关卡数据手放 |
| 砍得掉吗 | — | 不能 | 藤鞭可砍 |

判据是**会不会影响"怎么过关"**。草丛摇摆再好看，玩家也永远不需要为它改变路线——它住在装饰层，跟着地表瓦片自动生成，加房间零成本。藤蔓丛会破护罩，等于在说"这条路别想飞过去"——这是关卡语言，必须落在 `rooms.ts` 的物件表里，让设计者逐个摆放、让校验器能检查锚点合法性。

如果反过来把藤蔓也交给生成器随机撒，"护罩路线不受干扰"就从**设计事实**退化成**概率事件**：每次改装饰参数都可能悄悄把一丛藤蔓撒进毒云廊，而且没有任何测试能在摆放时抓住它。**会说话的东西（对玩家传达规则的东西）不允许随机。**

## 2. 摇摆 = "响应"而不是"模拟"

植被摇摆没有物理：不建弹簧、不算质量。就是三行状态机——

```
玩家判定盒(外扩一圈)与植被相交 → swayT = 0.55
每步 swayT -= dt
渲染偏移 = sin(time × 频率) × 幅度 × (swayT / 0.55)
```

触发瞬间给一个固定时长的"惊动预算"，渲染层用一个衰减的正弦把预算花完。这和真实物理毫无关系，但玩家完全买账——因为**交互反馈的重点是"我碰它了，它动了"，动得像不像藤蔓是次要的**。同理：泡泡的 wobble、花苞的呼吸、游魂的漂浮，全是 `sin(time × f + 相位)`，没有一个是真物理。

数据流上有个小设计：`decor.update(dt, particles, px, py)` 新增了玩家坐标参数。装饰层依然不知道 Player 类的存在（拿到的就是两个 number），依赖方向没变——**给数据，不给对象**，层与层之间保持这种最薄的接口。

## 3. 护罩是肥皂泡：一条规则说了两件事

"护罩蹭到藤蔓就破"同时是**机制**和**关卡语言**：

- 机制侧：`HangingVine.update` 里检查 `player.shieldT > 0 && rectHit(player.box, rect)` → 破。破裂复用泡泡的爆裂表现（音效+粒子），并且在毒雾里破会立刻结算伤害——护罩本来就不该是毒雾里的万能通行证，破在哪儿就按哪儿的规矩来。
- 关卡侧：由此得出摆放铁律——**只能靠护罩通过的区域附近不放藤蔓，或放尖端离飞行线 ≥40px 的高位短款**。(1,3) 毒云廊飞行线 y≈145、(1,5) y≈135，这两间的藤蔓尖端全部 ≤40。(0,4) 尖刺地上方同理收紧到 ≤30。

这条铁律没法用校验器完全自动化（"护罩路线"是几何推理，不是数据检查），所以用两层测试兜底：`vine-test` 场景3 直接开护罩飞一遍 (1,5) 毒雾层验证中途不破；`bubble-shield-test` 场景2 每次回归都完整飞一遍 (1,3)。**校验器管数据形状，功能测试管设计承诺——各管一段，别指望一个工具包打天下。**

## 4. 一井一泡：0.5 秒宽限在宽限什么

召唤第二个泡泡后，第一个 0.5s 后破裂。为什么不是"立刻消失"？

- 立刻消失在"骑着第一个泡泡、吹出第二个"的瞬间 = 脚下平台凭空蒸发，玩家会觉得是 bug；
- 0.5s 是**反应窗口**：感到泡泡开始闪烁示警 → 按 J 跳向新泡泡，是一条能学会的小节奏；
- 倒计时期间骑乘、鞭击照常——如果玩家在 0.5s 内鞭击旧泡泡转成护罩，那是合法操作，规则不跟玩家抢帧。

实现上就一个公开字段：`world` 在召唤时给场上所有旧泡泡设 `doom = BUBBLE_DOOM`，`Bubble.update` 开头倒计时、归零走既有 `pop()`。**新状态优先复用旧的消失路径**（pop 里音效、粒子、dead 标记都是现成的），不要为"被顶替的破裂"再造一套爆裂。

## 5. 血泪：贴边判定别按理论满跳算

vine-test 第一版永远不过：藤蔓尖端 y=120，满跳顶点理论值 25.6px，玩家头顶判定盒上缘扫到 y≈126.4——外扩 8px 后恰好 118.4 < 120，应该触发。实测**峰值差 0.2px** 没触发。

逐帧探针（记录 y 和 vy）还原真相：物理完全正常（vy 序列严丝合缝符合 224-980t），但起跳帧、落地探测、离地那一步的帧量化让实际顶点比理论值矮 1~2px。理论上是 `156 - 25.6 = 130.4`，实际 `132.0`。

教训进 §六 了：**涉及"极限能力刚好够到"的判定，留 ≥3px 余量，或者直接把内容放近一点**（本次把测试那丛藤蔓 h=2 加长到 h=3）。游戏手感里所有"差点够到"都该来自设计，不来自帧量化。
